# 아이템 후보 발굴

[편집 기준](../../references/editorial-standard.md)을 먼저 읽는다.

1. 조사 시각을 한국시간으로 표시하고 그 시각에서 직전 7일 업로드를 대상으로 삼는다. 뉴스의 기사 발행 시각과 영상 업로드 시각을 구분한다.
2. 뉴스 화제와 제공된 채널별 영상 데이터를 **한 후보 풀**로 합친다. 자체 채널 자료는 우선 검토한다. B tv 뉴스 `UCQeRytUmPXlZN-tgmDnCM2w`, 뉴브 `@newve_with_btvnews` 각각 롱폼 3개·쇼츠 3개를 현재 누적 조회수로 표시한다. 도구가 있으면 `../../scripts/youtube_rank.py`를 사용한다. API 키가 없으면 조회 결과를 꾸미지 말고 `미연결`로 기록하고 공개 페이지에서 수동 확인하거나 제작진이 가져온 목록을 사용한다.
3. 영상 URL, 제목, 채널, 업로드 시각(KST), 누적 조회수, 조회 시각(KST), 형식 판별 근거를 적는다. 쇼츠 자동 분류는 완전하지 않으므로 판별이 필요한 항목은 검토 표시한다. 조회수는 `7일 증가분`으로 부르지 않는다.
4. 같은 사건의 여러 영상을 한 이슈로 묶는다. 높은 조회수만으로 선정하지 말고 최근성, 구체적 사건의 힘, 취재 가능성, 기자 3명의 30분 대화 가능성, 출처 신뢰도, 자연스러운 지역 연결을 확인한다. 지역 연결은 우대 요소이지 범용 주제로 바꿀 이유가 아니다.
5. **후보 3개**만 우선순위와 간략한 근거로 노션에 붙여넣기 쉽게 제시한다. 각 후보에 `핵심 고유명사`, `방송 질문`, `왜 지금`, `지역 연결(확인/조사 필요/없음)`, `핵심 출처 URL`, `자체 채널 신호`를 붙인다. 자체 채널의 상위 3개씩은 별도 참고표로 제시하되 12개 영상 전부를 방송할 목차로 쓰지 않는다.
6. 후보 추천에서 멈추고 제작진의 선정을 기다린다. 명시적인 자동 선정 권한이 없으면 대본을 쓰지 않는다.

랭킹 페이지 접근 실패를 순위 부재로 해석하지 않는다. 확인하지 않은 조회수, 업로드 시간, 근거를 만들지 않는다.
